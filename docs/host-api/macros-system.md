## 3. Application lifecycle (LifecycleStateMgr, 10 ms tick, pushdown stack)
States (exact names from `STATE ENTERED/EXITED` lines, 6 full boots in logs): `Booting → Constructing → AwaitingTos → InitObservability → InstallationRequired → ResolvingConflicts → OfferingFanControl → SettingUpAddons → ScanningHardware → LoadingEffects → ActivatingServices → Running` then pushed sub-states on top of Running: `Onboarding` (pushed/popped immediately when main flow finished; stays on stack otherwise — shutdown pops `Minimized, Onboarding, Running`), `Minimized` (window hidden), `Suspending` (stack `Running / Minimized / Suspending`), `Resuming` (transient), `ShuttingDown` (terminal). Lighting-side FSM (CanvasRenderThread, independent): `Resuming → Finding (EffectFinding: Searching for '<id>' / Entered / Found '<name>' / Exiting) → EffectRunning: Activated '<name>'` → `Running` (`LightingManager::Process Current lighting state`).
