# packaging/

Distribution artifacts for Lightloom. Release builds are produced by
`.github/workflows/release.yml` (cargo-dist planned; cargo-auditable + CycloneDX SBOM
today). Nothing here is signed yet; Authenticode via SignPath OSS is the planned step
for Windows (see the SIGNING block in the release workflow).

Only `systemd/`, `udev/`, `sysusers.d/`, `msix-identity/` and `wix/lightloom.ico` (the app icon, rendered from
`docs/brand/lightloom-icon.svg`) are real files at the moment; everything else is
a placeholder with the file names already decided so later milestones (M4 Windows
packaging, M7 Linux packaging) drop files into known places.

## Windows (MSI, winget)

- The **portable build** is what the release workflow publishes today: one directory
  (zipped) staged by `tools/package/stage-windows.ps1` with `lightloomd.exe`, `lightloom.exe`,
  `lightloom-renderer.exe` and its CEF runtime, `ui/`, `plugins/`, `effects/`, the license
  texts and `THIRD-PARTY/CEF-Chromium-CREDITS.html`. Unzip anywhere and run
  `lightloomd.exe --open`; settings go to `%LOCALAPPDATA%\Lightloom` and `%APPDATA%\Lightloom`.
  About 400 MB unpacked, most of it Chromium.
- The MSI installs `lightloomd.exe`, `lightloom.exe`, `lightloom-renderer.exe` plus the CEF
  runtime under `%ProgramFiles%\Lightloom`, registers the `lightloom://` URL scheme and an
  optional per-user autostart entry. It never installs a kernel driver.
- The privileged helper `lightloom-iobroker` (Windows service, LocalSystem) is **not** part
  of the default MSI feature set; it is installed on explicit opt-in by `lightloom-setup`
  (M5), together with PawnIO.
- winget manifests are generated from the MSI (`wingetcreate update`) after a release is
  published and signed.

## Linux (systemd user unit, udev)

- `systemd/lightloomd.service` is a `systemd --user` unit: copy to
  `~/.config/systemd/user/`, then `systemctl --user enable --now lightloomd`. It expects the
  daemon at `~/.local/bin/lightloomd` (the AppImage/Flatpak builds ship their own unit with
  the correct path).
- `udev/70-lightloom.rules` is generated from the first-party plugin manifests by
  `lightloom udev generate --plugins plugins --out packaging/udev/70-lightloom.rules`; a
  `lightloom-cli` test fails when it is stale. It tags only the `hidraw` (or `usb_device`,
  `tty`) node of each claimed VID:PID with `uaccess` (an ACL for the logged-in seat user)
  and puts the `/dev/i2c-*` adapters Lightloom uses (by adapter name) in group `i2c` for
  SMBus plugins. Install steps:
  `udev/README.md`. With imported plugins, generate your own file the same way.
- `sysusers.d/lightloom.conf` creates the `i2c` group (`systemd-sysusers`).
- `modules-load.d/lightloom.conf` loads `i2c-dev` at boot (the `/dev/i2c-*` nodes).

## AppImage / Flatpak

- AppImage bundles CEF and the renderer; built with linuxdeploy in CI (M7).
- Flatpak uses the `org.freedesktop.Platform` runtime; device access through the
  `--device=all` permission (hidraw) and the `/dev/i2c-*` rule above. Portals are used for
  screen capture (`engine.zone`) and audio (`engine.audio`).
