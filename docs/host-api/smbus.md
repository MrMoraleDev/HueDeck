## 2. Two bus objects (native classes)

Native RTTI: `.?AVI2CBusWrapper@@` (free-address) and `.?AVI2CBusWrapperFixedAddress@@` (fixed), owned by `I2CBusManager` (`Signal\Discovery\I2CBusManager.cpp`), with `I2CBusDescriptor` / `I2CBusDeviceDescriptor` lists. The concrete backend for the AMD chipset bus is `AMDI2CBus` (`AMDI2CBus::WriteQuick/ReadByte/WriteByte/ReadWord/WriteWord/WriteBlock/ReadBlockBytes`).

- **FreeAddressBus** (`Scan(bus)` argument, class `I2CBusWrapper`): every transfer takes the 7-bit `address` as first parameter. `bus.Type()` returns `"Free"`.
- **Fixed bus** (global `bus` in Initialize/Render/Shutdown and all helper classes, class `I2CBusWrapperFixedAddress`): address is bound; same methods minus the `address` parameter. `bus.Type()` returns `"Fixed"`. `String(bus)` starts with `"I2CBusWrapperFixedAddress"` (hack used in `Gigabyte_Gen1_GPU.js:109`, `Gigabyte_Gen2_GPU.js:103`: `if(String(bus).startsWith("I2CBusWrapperFixedAddress"))`). Identity methods (`Vendor/SubVendor/Product/SubDevice/Name/IsXBus/GetAddress`) exist on both.

Plugins model this explicitly with `XInterfaceFree` / `XInterfaceFixed` classes (ENE_RAM, Crucial, AsusSMBus) whose "Free" methods guard with `IsFixedBus()` and log `Bus Interface must be a "Free" Type to use this function! This can only be done inside of the Scan() export.`

## 6. Scan pipeline & engine behaviour (from log + exe strings)

Startup (main thread, 11:22:55–58):
1. `Gathering System Mutexes...` → for each of SMBus, ISA, PCI, CorsairLink, UsbSensor: `Attempting to acquire X mutex...` → `X Mutex does not exist, creating...` → `Successfully Created X mutex!` (or `Successfully Acquired`). Logger `SignalRGB.mutex.<X>`.
2. `Found bus with Vendor 0x1022, and Device id 0x790b` (PCI config scan via driver) → `Internals Driver is OPEN!` (`\\.\SignalIo`; version check `Mismatched SignalIO Driver. Read Version [1.3.7.0], But Wanted [1.3.9.0]`; if outdated: `InstallationRequired ... blocking until installed`).
3. `I2CBUS - Created PIIX4 Bus on Base Address: b00, with Vendor: 1022, Device: 790b` / `PIIX4 Bus at 0x0b00 host status register: 0x00`; same for `b20`. ## 8. PIIX4 / AMD FCH specifics

AMD FCH SMBus PCI 1022:790B; SMBus host base 0xB00 (primary) and 0xB20 (secondary — the FCH exposes two SMBus host controllers; both created and scanned). I/O-port access through `\\.\SignalIo` (driver provides port I/O, PCI config, SMBus; "Internals"). Host status register read at creation; 0xFF ⇒ controller absent/disabled. Observed per-op latency ≈ 1–3 ms (WriteQuick+1 ms pause). Transaction timing in plugins (30 ms between ENE reads) is protocol-driven, not engine-driven. Intel (i801/ICH) support: **UNKNOWN** (no strings; the plugin comments say "AMD / INTEL" but may be aspirational).

## 11. RAM address remapping

ENE/Aura (`ENE_RAM.js:733-851`): all ENE DIMMs power up at 0x77 (Aura) ; first software to touch them must move each DIMM to a unique address. Loop up to 8 slots: `WriteQuick(0x77)` (<0 ⇒ nothing left) → pick first *free* address (WriteQuick<0) from the potential list → `WriteRegister(0x77, 0x80F8, slotIdx)` (SetChannelIdx) + `WriteRegister(0x77, 0x80F9, freeAddr<<1)` (SetStickAddress, 8-bit address) with 1 ms pauses; XTREEM variant uses 0xE0F8/0xE0F9. ENE register access = `WriteWord(addr, 0x00, bswap16(reg))` then `WriteByte(addr, 0x01, val)` / `ReadByte(addr, 0x81)` / `WriteBlock(addr, 0x03, n, data)`.
Crucial Ballistix (`Crucial Ballistix Ram.js:232-276`): source 0x27; up to 4 slots; `WriteRegister(0x27, 0x82EE, slot)`, `WriteRegister(0x27, 0x82EF, freeAddr<<1)`, `WriteRegister(0x27, 0x82F0, 0xF0)` (apply). Direct mode: 0x820F=0xCF, 0x82EE=0, 0x82EF=0x10, 0x82F0=0x84; colours as three 8-byte planes at 0x8300/0x8340/0x8380 inside TransactionLock. Remap persists until power cycle, so a second scan finds sticks already at the remapped addresses (log: `Address [119] is unpopulated. Avoiding Ram address remap.`).

## Engine requirements (summary)

- Plugin loader: treat Type()==='SMBUS' (case-insensitive) as I2C class; run Scan(bus) sequentially per plugin x per bus on a scan thread, no global `bus`; create one device instance (own thread, fixed-address wrapper bound as global `bus`) per returned address; uid 'I2CBUS:<addr>[:Slot:<n>]'.
- Two JS wrapper classes: FreeAddressBus (methods take addr first) and FixedAddressBus (addr bound); both expose Vendor/SubVendor/Product/SubDevice/Name/Type('Free'|'Fixed')/GetAddress/IsSystemBus/IsAMDBus/IsNuvotonBus/IsNvidiaBus/IsAMDGpuBus/log(msg,{toFile,hex})/pause(ms); String(fixedBus) must start with 'I2CBusWrapperFixedAddress' (Gigabyte hack).
- Transfer methods with validation and int status (0 ok, negative fail; reads return byte/word or negative): WriteQuick(addr), ReadByte([addr],reg), WriteByte([addr],reg,byte), ReadWord([addr],reg), WriteWord([addr],reg,word16 LSB-first), WriteBlock([addr],reg,len,data[]), WriteBlockWithoutRegister([addr],len,data[]), ReadBlockWithoutRegister([addr],len)->[code,bytes[]], ReadBlockBytes(reg,len)->[code,bytes[]] (fixed), ReadByteWithoutRegister(addr) (NvAPI only), TransactionLock()/TransactionUnlock() (fixed), deprecated FetchRamInfo()->string.
- Validation messages/limits: addr/reg/byte 0..255, word 0..65535, len 0..max, data must be array, array size <= len; per-bus max block length; 'Bus is no longer available' when backend torn down.
- Backends: (a) AMD FCH PIIX4 SMBus host at I/O 0xB00 and 0xB20 (PCI 1022:790B) via a kernel port-I/O driver (SignalIo equivalent), status-register sanity check at creation; (b) NVIDIA per-GPU I2C via NvAPI with PCI-ID exposure; (c) AMD per-GPU I2C via ADLX; (d) Nuvoton SuperIO SMBus via LPC 0x2E/0x4E under ISA mutex; Intel i801 optional/unknown.
- Cross-process locking: named mutexes Global\Access_SMBUS.HTP.Method (around every SMBus transaction and across TransactionLock), Global\Access_ISABUS.HTP.Method (LPC/SuperIO), Global\Access_PCI (PCI config), with acquire/create/access-denied/stuck-owner handling and hold-time metrics; abort all I2C if SMBus mutex cannot be created.
- Scan gating: wait for WMI RAM/motherboard info (systeminfo) and for ConflictingProcesses to exit (with timeout); user toggle to disable SMBus scanning; crash counter to skip scan after repeated crashes; retry driver-gated buses when driver becomes available; legacy '[DEPRECATED] I2C Device Scan' no-op stage.
- Persist cache/i2c_scan_results.json as [{address:int, busName:string, pluginFile:string}], compare after each scan, log misses.
- Modules: @SignalRGB/systeminfo {GetMotherboardInfo()->{manufacturer,model}, GetRamInfo()->[{partNumber,manufacturer}], GetBiosInfo()->{releaseDate}} and @SignalRGB/permissions {permissions()->{fans,lighting,macros}, setCallback(fn)}; keep device.getMotherboardName()/bus.FetchRamInfo() as deprecated shims.
- Logging: bus.log with {toFile:true} prefixed by bus Name() under root logger; per-plugin 'scan took N ms'; loggers devices.i2c_scan, devices.i2c_scan.cache.read/write, mutex.<Name>; ConflictMitigator watcher per I2C device uid.

## HueDeck: what differs from SignalRGB (M5)

HueDeck implements the surface above in `crates/huedeck-plugin-host` (`js/host.js`
`nativeBusMembers`, `src/bus.rs`, policy in `src/smbus.rs`). Where it deliberately differs:

- **`SmbusAddresses()` (HueDeck extension, required).** An SMBus plugin must export the
  7-bit addresses (0x03..=0x77) its `Scan(bus)` may touch and its devices may live at.
  Plugins without it (every SignalRGB SMBus plugin) are listed as skipped with that reason
  and never run, so no third-party `Scan()` writes reach a chipset bus.
- **`SmbusBuses()` (HueDeck extension, optional).** The bus kinds `Scan(bus)` is offered:
  `"system"`, `"amd"`, `"intel"`, `"nvidia"`, `"amdgpu"`, `"nuvoton"` (`"any"` or absent:
  any). GPU buses are offered only to plugins whose `BrandGPUList()` names the card (all
  four PCI ids); chipset buses only to plugins without a `BrandGPUList()`.
- **Two-phase allowlist.** During `Scan(bus)` only the plugin's `SmbusAddresses()` are
  reachable. The addresses `Scan()` returns (integers in that window, at most 8, no
  duplicates; anything else is dropped) become the bus allowlist; a device session is
  bound to its one address and must find it on that list. When two plugins return the
  same address on one bus, the first one keeps it.
- **`SmbusDeniedRegisters()` (HueDeck extension, optional).** Registers the host never
  lets the plugin write, at any address and in every phase (for a register-less write, its
  first byte): save-to-flash and similar commands. The MSI GPU plugin lists 0x3F
  (`MSI_GPU_REG_SAVE`). The manifest repeats them as `smbus.deniedRegisters`.
- **DIMM deny ranges.** Writes and Quick commands to 0x50-0x57 (SPD EEPROM) are refused on
  every bus. On buses that may reach the DIMMs (chipset: System, AMD, Intel; and Nuvoton)
  also 0x30-0x37 (SPD write protect / page select), 0x48-0x4F (DDR5 PMIC) and 0x50-0x5F
  (DDR5 RCD, 24RF08-class EEPROMs a Quick write can corrupt), whatever the plugin; reads
  are allowed. GPU buses keep the other addresses (the ASRock GPU plugin quick-writes
  0x36 on its ADLX bus).
- **Receive Byte on chipset buses.** `ReadByteWithoutRegister` works on AMD PIIX4 and Intel
  buses as well as NVIDIA ones (SMBus protocol BYTE); SignalRGB refuses it outside NvAPI by
  policy. OpenRGB's RAM detection probes with it.
- **`WriteBlock` is an SMBus Block Write**: register, a count byte, then the data
  (`[len, data...]` after the register on NvAPI, protocol 5 on PIIX4). Data longer than
  `len` is clipped (logged once), shorter data zero-padded. Blocks are 1..=32 bytes.
- **Return values.** Failures never throw: on NVIDIA buses the plugin gets NvAPI's own
  negative status (e.g. -105), elsewhere -1. Argument errors throw `RangeError` /
  `TypeError` with the engine's messages (`WriteByte(): Register must be a number between
  0 and 255`, `WriteBlock(): Data must be an array.`). The fixed bus has no `WriteQuick`.
- **TransactionLock** holds the bus against the other sessions on it; another session
  waits at most 250 ms, then its operation fails. It also asks the bus for a lease
  (100 ms): on a chipset bus the I/O broker's `BusLock`, on an NVIDIA bus the NvAPI
  worker; both keep the global SMBus mutex across the locked operations, so other
  programs' transfers cannot land in between. HueDeck's `TransactionLock()` returns
  whether the bus is held (`false`: nothing should be sent); SignalRGB's returns nothing,
  so plugins test `=== false`. A lock still held when `Render()` returns is released by
  the host, which logs "bus: Transaction Lock wasn't unlocked before Render() returned!"
  once.
- **Frame rate.** An SMBus session calls `Render()` at most every 33 ms (about 30 fps,
  OpenRGB's `TimeToSend` for the MSI GPU controller), whatever the canvas rate; the latest
  frame is rendered.
- **GPU I2C** (NvAPI) runs in HueDeck's own process, every transfer under
  `Global\Access_SMBUS.HTP.Method` (50 ms bounded wait; `NVAPI_DEVICE_BUSY`, -108, when
  another program keeps it), on one worker thread that addresses the card by PCI bus and
  ids. A request still queued when its caller gave up (500 ms) is dropped, never sent late.
- **Chipset buses on Windows** are served by the HueDeck I/O broker (`huedeck-iobroker`,
  a LocalSystem service registered once with `huedeck-setup --smbus`) through the PawnIO
  driver's signed `SmbusPIIX4` module; HueDeck's own processes never open PawnIO. Every
  transfer runs under `Global\Access_SMBUS.HTP.Method` (bounded wait; a busy mutex fails
  the operation), at most 2000 operations per second, and the broker refuses the DIMM
  ranges again on its side and writes only to its own allowlist of first-party chipset
  addresses (0x20-0x23, 0x27, 0x39-0x3C). `ReadBlockBytes`, `WriteBlockWithoutRegister` and
  `ReadBlockWithoutRegister` are refused on chipset buses, as on SignalRGB. Without
  PawnIO (official edition 2.2.0 or later) or the broker, the run says what is missing;
  HueDeck never installs PawnIO.
- **Conflicts.** SMBus discovery and SMBus sessions never run while `SignalRgb.exe`,
  `OpenRGB.exe` or a vendor lighting service that drives the same controllers runs (MSI
  `LEDKeeper*` / `LightKeeperService*` / `Mystic_Light_Service`, ASUS `LightingService`,
  Gigabyte `RGBFusion`); unlike HID, `--ignore-conflicts` does not override this (`Scan()`
  itself may write). They are looked for again every second while SMBus devices run: one
  that starts stops the SMBus sessions (daemon) or ends the run (CLI), `Shutdown()`
  included. Only one HueDeck process drives SMBus at a time (`Global\HueDeck.SmbusOwner`).
  A rescan stops the SMBus sessions before the plugins' `Scan()` runs. SMBus is opt-in:
  `--smbus` on the CLI, `[smbus] enabled` or the dashboard setting in the daemon.
- **Dry-run.** With `--dry-run` every bus write, in `Scan()` too, is recorded and reported
  successful but never sent; reads still reach the device.
- **Device keys.** `smbus:<vendor>:<device>:<subvendor>:<subdevice>@<instance>:<addr>` in
  lower-case hex, e.g. `smbus:10de:2504:1462:3903@pci01:68` (instance: the GPU's PCI bus,
  or the PIIX4 port base `0b00` / `0b20`).
