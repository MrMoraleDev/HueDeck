## 4. Engine composition: channel → colour stream
1. Persistence: `HKCU\Software\WhirlwindFX\SignalRgb\devices\<vid:pid:serial>\<ChannelName>` = JSON array (QSettings string) of component instance objects in chain order (full component JSON + `ComponentId`). Each instance also has `lighting\endpoint\<ComponentId>\position {x,y}` and optional `scale {"x","y"}`/`enabled` — it is a first-class canvas endpoint (subdevice) that the user drags in Layouts, with its own `Width×Height` footprint. Global default scale `lighting\endpoint scale={"x":40,"y":40}`; canvas = 320×200 effect page sampled through layout grid (`layouts gridSize=4`).
2. Per frame, for every component instance in a channel, in array order: sample the layout canvas at each `LedCoordinates[i]` (component-local pixel → canvas pixel via the instance's position/scale/rotation), apply global brightness, endpoint colour correction (`RedBalance/GreenBalance/BlueBalance/MinBrightness`) and per-LED colour overrides (`/colors/`, "Loaded Led color overrides"), then write into the component stream at `LedMapping[i]`.
3. `channel.getColors("Inline", order)` = concatenation of component streams in chain order, each `LedCount*3` bytes, bytes permuted by `order`; `"Separate"`/`"Seperate"` = `[R[],G[],B[]]` of the same concatenation; `getComponentColors(id, …)` = a single component's stream; `ledCount/LedCount()` = Σ LedCount. No padding/alignment between components — hardware slotting (Corsair 34-LED fan slots) is done by the plugin.
4. Limits: `ledLimit` (channel) and device `ledLimit` are UI budgets ("They'll get cut off at the limit"); whether `getColors` truncates is UNKNOWN — plugins truncate themselves (`RGBData.slice(0, 238*3)` `Corsair_Lighting_Commander_Core.js:170`, `Math.min(LedCount(), limit, …)` `PCDOCK_Light_strip.js:217`). Safe implementation: truncate the concatenated stream to `min(channel.ledLimit, remaining device budget)`.
5. Empty/placeholder: a channel declared with `defaultLedCount>0` (or implicit `ledLimit/2`) and no persisted components gets one `Default Strip - N` instance; UI removes it automatically when the first real component is added (`onlyHasDefaultComponents`). The UI "Setup Your RGB Components" warning (`configuredWarning`, `setIgnoreConfigured`) is raised while only defaults exist.
6. Identify/pulse: UI "Pulse Channel"/"Pulse Component" sets `identifying=true` with a per-channel `identifyingColor`; `shouldPulseColors()` → true; `getChannelPulseColor(name)` returns that colour; a kill-timer stops it ("Channel pulse kill timer triggered - forcing pulse stop"). Plugins render it over a fixed LED count regardless of components.
7. Component library load: scan `Signal-x64\Components\**\*.json` then `<UserDirectory>\Components` (registry `UserDirectory=%USERPROFILE%/Documents/WhirlwindFX`), user entries override by `ProductName`; log "Component Scan Started/Finished"; brand/type filter lists are generated from the loaded set; validation messages as in §3; picker sorts by Name/Led Count asc/desc, filters by brand/type/text; also a web "component builder" at `marketplace.signalrgb.com/components?mode=picker`.

## HueDeck implementation notes (M2)

What `crates/huedeck-plugin-host/src/children.rs` and `js/host.js` (device mode) do
where the contract above leaves a choice:

- **Channel setup comes from the caller.** A session gets the component instances
  per channel name (`SessionOptions::channel_components`). `huedeck light|rainbow|bench
  --signalrgb` imports SignalRGB's arrays read-only from
  `HKCU\Software\WhirlwindFX\SignalRgb\devices\<vid:pid:serial>\<channel>`; values
  under that key that are not component arrays (plugin property values) are ignored.
- **Placeholder.** A channel with no entry gets one `Default Strip - N` (N = the third
  `addChannel` argument, else `ledLimit / 2`; none when N is 0). An entry that is an empty
  array stays empty: the user removed every component.
- **Limits.** `channel.ledCount`, `getColors()` and `device.getLedCount()` agree: the sum of
  the components' `LedCount`, cut at the channel limit and at what is left of the device
  limit (`SetLedLimit`, channels in creation order). Plugins that send `ledCount` LEDs never
  overrun their controller.
- **Re-adding a channel** keeps its components and updates the limit (logged only when it
  changes); `removeChannel` drops it, a later `addChannel` gets a fresh setup.
- **Placement.** Every subdevice and component instance is its own canvas endpoint:
  `SessionOptions::placements` by uid (`<device key>:<subdevice id>` or `ComponentId`),
  otherwise fitted to the canvas (`Placement::fit`: uniform scale, centred; refitted when
  `setSubdeviceSize` changes the grid). Layout import from SignalRGB is M4.
- **Identify/pulse** has no UI yet: `shouldPulseColors()` is `false`,
  `getChannelPulseColor()` is `#009EDB`.
- **Errors** follow the exe texts (`Failed to find subdevice with name: …`,
  `device.subdeviceColor(): Out of bounds error. …`, `ERROR: Led names and positions vary
  in length! …`), are logged once per distinct message and never throw; out-of-range
  samples are black.
- **`@SignalRGB/permissions`** grants every permission of every partner (`MSI`, `Lian-Li`)
  and never calls back; **`@SignalRGB/systeminfo`** reports the SMBIOS baseboard
  (`model` = `Win32_BaseBoard.Product`), BIOS (`releaseDate` as `YYYY-MM-DD`) and populated
  memory slots (`manufacturer`, `partNumber`, …).
