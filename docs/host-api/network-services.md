## 1. Lifecycle of a `Type()==="network"` plugin

### 1.1 Two JS contexts from one file
1. **Service context** (one per file, own thread: log `Starting discovery thread for <path>` / `Stopping discovery thread for <path>`; class `DiscoveryServiceThread`). Module is evaluated; host reads `export function Name()` and `export function DiscoveryService()`; host does `discovery = new DiscoveryService()` and exposes globals **`service`** (host QObject `DiscoveryService`), **`discovery`** (the JS instance itself — all `discovery.X` members used by plugins/QML are plugin-defined), **`theme`** (UTF-16 strings `service`,`theme` registered as globals; used only by QML). Exports `Initialize/Render/Shutdown` are NOT called here.
2. **Device context** (one per announced controller, own thread, "Engine Thread"): same file re-evaluated with globals **`device`** (normal plugin device API), **`controller`** (plain-data snapshot of the object passed to `service.announceController`; nested objects/arrays preserved: PhilipsHue.js:112 `controller.areas[controller.selectedArea].lights`, :353 `controller.lights[light].name`), ControllableParameters properties as globals, and modules/features (`udp`, `base64`, `dtls`). Exports `Initialize()`, `Render()` (looped), `Shutdown(suspend:boolean)` are called; `on<Prop>Changed()` exports are called on setting change (Twinkly.js:61-71, SRGBmods-WLC.js:144-151). Binary string `service.controller | controller | Initialize()` confirms `controller` is injected before `Initialize()`.

## Engine requirements (summary)

- Plugin crawler: treat a .js with `Type()==='network'` + exported `DiscoveryService` as a *service*, not a device; register `{Name(): path}`; scan bundled Plugins, Documents\WhirlwindFX\Plugins and every addon clone recursively (all plugin types + Components\*.json + sibling .qml); later duplicates of VID/PID override earlier ones; cache scan results keyed by a library hash.
- Per service: dedicated thread + fresh JS module instance; construct `new DiscoveryService()`; expose globals `service` (host object), `discovery` (= the constructed JS object), `theme`; read `IconUrl, MDns[], Hosts, UdpBroadcastAddress (default 255.255.255.255), UdpBroadcastPort, UdpListenPort`; call `Initialize()` once, `Update()` on a periodic timer (~1 s suggested), `Discovered(value)` per UDP datagram / mDNS add-update, `Removal(value)` on mDNS removal; log 'not implemented' warnings when missing.
- UDP discovery sockets: open a broadcast socket bound to UdpBroadcastPort (join multicast group when address is multicast, enable SO_BROADCAST), plus a listener bound to UdpListenPort (0 = ephemeral); deliver every datagram from either socket to `Discovered({id: senderMAC via ARP ('aa:bb:cc:dd:ee:ff' lowercase/uppercase per Twinkly/Cololight usage), ip, port, response: <payload as string>})`.
- mDNS/DNS-SD browser (equivalent of QMdnsEngine) on UDP 5353 shared by all services: per `MDns` type deliver `{hostname (with trailing '.'), name, port, id, ...TXT records flattened, ip?}`; implement `service.resolve(hostname, cb)` calling back once per A/AAAA record with `{protocol:'IPV4'|'IPV6', ip}`.
- `service` API: log(msg, {pretty}) → per-service console; controllers (array of wrappers exposing `id` and `obj`); addController/updateController/removeController/announceController/suppressController(obj) with 'must be an object'/'must have an id property' validation and >50 leak warning; getController(id)/hasController(id); getSetting/saveSetting/removeSetting(id,key[,value]) persistent per-service KV store rejecting '/' and '|' (value undefined = delete); broadcast(string) over the broadcast socket; resolve(); hideSettings/showSettings.
- announceController(obj) must deep-copy the controller's enumerable data (including nested objects/arrays) into a new device-context JS engine as global `controller`, then run `Initialize()`/`Render()` loop/`Shutdown(suspend)` with the full device API (setName, setImageFromUrl/Base64, SetLedLimit, addChannel(name,limit[,default]), channel(...).{ledCount,LedCount,LedLimit,SetLedLimit,shouldPulseColors,getColors(order,fmt)}, getChannelPulseColor, createColorArray(color,count,order,fmt), color(x,y), setSize, setControllableLeds, addProperty/removeProperty, subdevice API, SetIsSubdeviceController, pause, log, addFeature) plus `on<Prop>Changed` dispatch; suppressController must stop that engine (call Shutdown) and remove the device; updateController must refresh the UI model.
- Modules resolvable as `@SignalRGB/udp`, `@SignalRGB/tcp`, `@SignalRGB/base64` (+ serial, performance, appInfo, systeminfo, permissions, Errors): socket object with on(event,cb) for connected/connection, disconnected/closed, listening, message, error(code,message); bind(port), connect(host,port), disconnect(), send(string|byte[]) → bytes or -1, write(byte[],host,port), close(), address(){port}, remoteAddress(), state + enum constants (UnconnectedState…ListeningState, BoundState); message callback receives an object with at least `.data` (string). TCP sockets must be refused inside the service context.
- Legacy features via device.addFeature(): 'udp' → global `udp.send(host, port, byte[], endianness)` with 8192-byte cap; 'base64' → global `base64.Encode(byte[])→string` / `base64.Decode(string)→byte[]` (module exports are lowercase encode/decode); 'dtls' → global `dtls` with createConnection(host,port,pskIdentity,pskKeyHex), send(byte[],endianness?)→int, hasEncryptedConnection(), CloseConnection(), onConnectionEstablished/onConnectionClosed/onConnectionError(cb), ignoreSslErrors(bool) implementing DTLS 1.2 PSK (Hue entertainment, port 2100).
- Global `XMLHttpRequest` in BOTH contexts supporting open(method,url,async) with async=false (blocking the plugin thread and letting callbacks mutate closure variables before `send()` returns), setRequestHeader, onreadystatechange(readyState 4), status (0 on connection failure), response/responseText, methods GET/POST/PUT/DELETE, plain-HTTP targets on the LAN; plus `console.log`.
- QML UI host: load `<plugin>.qml` next to the .js (bare `Item` root, implicit QtQuick/Controls Material imports), inject `service`, `discovery`, `theme` (primarytextcolor, secondarytextcolor, primaryfont, secondaryfont, background2/3/4, warn, radius, scrollBar), expose controllers as a list model with `modelData.obj`, allow cross-thread calls to `discovery.fn()` and `obj.fn()` (callDiscoveryFunction/callControllerFunction proxies), provide custom types SButton, SIconButton, SComboBox, SContextMenu, STextField and `qrc:/icons/Resources/Icons/Material/*.svg`; hot-reload on file change. (Linux port: replace with any UI toolkit but keep the same data contract.)
- Addon manager: handle `signalrgb://addon/install?url=` (confirm in settings UI), clone with libgit2 into `<cache>/addons/<md5(url utf8)>/`, on every startup fetch + fast-forward `main` sequentially before plugin scan (log the Repository.cpp sequence), reset corrupt repos, support a built-in default list and a blacklist from remote config, enable/disable per addon, block shutdown while updating.
