## Key tables

OpenRGB builds the key list with its KeyboardLayoutManager: the base blocks for the size
(tenkeyless or full), the LED values from the keymap in that key order, then the regional
overlay picked from the firmware string:

- first character `2`: ISO (the ANSI backslash above Enter is removed);
- `3`: JIS (only alternate names change: every key stays);
- anything else, or no answer: ANSI (`ISO_#` and `ISO_<` are removed).

The Pro L then gets P1-P4 at the end of row 0 (values 101, 109, 117, 119). Results: Pro S /
Pro L White 87 (ANSI), 88 (ISO), 89 (JIS) keys on 17 x 6; Pro L 108 / 109 / 110 keys on 21 x 6.
Each key's LED value is its slot in the 128-colour direct buffer.

## Protocol

Every command is a 65-byte output report: report id `0x00`, the command bytes, zeros. OpenRGB
reads the keyboard's answer after each one (`hid_read`, blocking); HueDeck reads with a 50 ms
timeout (`CM_KEYBOARD_TIMEOUT`). hidapi hands the answer over without the report id; HueDeck's
`device.read` puts it first, so C++ index `i` is HueDeck index `i + 1`.

**Start** (the controller's constructor, `_GetFirmwareVersion`): `41 00` (control mode
"firmware"), then `01 02`; the answer from index 4 is the firmware string (`<layout>.<minor>.<major>`).
OpenRGB then shows Direct as its first mode and sends no mode packet.

**Every frame** (`SetLeds`): `41 02` (manual LED control), then eight packets
`C0 02 <2 * i> 00` + 16 colours (R, G, B) for LED values `16 i .. 16 i + 15`. HueDeck skips an
unchanged frame and resends it after 1 s.

**Shutdown.** OpenRGB has no exit step (`CMKeyboardV1Controller::Shutdown` is empty). HueDeck
sends `41 00` (`MODE_FIRMWARE`, the command OpenRGB's own firmware query starts with): the
keyboard goes back to its own stored lighting.

## Left out

- `50 55` (`SaveProfile` / `SaveActiveProfile`): a write to the keyboard's memory. Never sent.
- `51 28` / `51 2C` / `41 01` (`SetActiveEffect`, `SetEffect`, `SetCustomMode`): hardware-effect
  writes. OpenRGB sends them when a user picks an effect mode, and also when the user re-picks
  "Direct", because `InitializeModes` maps value `0x02` first to Direct and then overwrites it with
  Spectrum Cycle (both use value 2), so that switch writes Spectrum Cycle's parameters. The
  per-frame path does not need them (it sets manual control itself), so HueDeck never sends them.
- `51 00 00 00 <profile>` (`SetActiveProfile`) and the `52 ...` reads: not used by V1 Direct.
- `SetSingleLED` (`C0 01 ...`): OpenRGB's single-LED path, not needed.

## Untested

All three product ids. Open questions for a hardware test: whether `41 00` at shutdown really
restores the stored lighting on every firmware; whether the Pro L White has the Pro L layout
(OpenRGB gives it the Pro S table).
