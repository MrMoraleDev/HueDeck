# E1.31 / sACN output

The plugin is `plugins/e131/`. It sends LED colours with E1.31 (Streaming ACN, ANSI
E1.31-2018) by unicast to a receiver on UDP port 5568: WLED, ESPixelStick, Falcon, Advatek and
most pixel controllers and DMX gateways.

**Status: untested.** Nobody on the project owns an E1.31 receiver. The packets are worked out
from the standard and checked only against the mock net (`plugins/e131/tests/e131.test.mjs`).

## Adding a receiver

- **Add by IP:** `discovery.forceDiscover(ip)` adds a controller with the id `e131-<ip>`, name
  `E1.31 <ip>`, port 5568, and a **CID**: 16 random bytes made a version-4 UUID (RFC 4122),
  generated once when the receiver is added. The list `[{ ip, cid }]` is kept in the plugin
  settings (`e131` / `controllers`), so the receiver sees the same source (CID) after a restart.
  The service sends nothing to the receiver.
- **Forget:** `discovery.forgetController(id)` stops the device and removes it (and its CID).

## Parameters

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `universe` | number 1..63999 | 1 | Universe of the first LED |
| `startChannel` | number 1..512 | 1 | DMX slot of the first LED's first byte in that universe |
| `ledCount` | number 1..1700 | 170 | RGB LEDs on the receiver |
| `colorOrder` | RGB, RBG, GRB, GBR, BRG, BGR | RGB | Byte order per LED |
| `priority` | number 0..200 | 100 | E1.31 source priority |

Out-of-range values are clamped with a log line. Changing universe, start channel or LED count
re-lays out the strip; universes no longer used get three Stream_Terminated packets.

## LEDs to universes

Rule: **170 RGB LEDs (510 slots) per universe, no LED split across two universes.** The first
universe starts at `startChannel` and holds `floor((513 - startChannel) / 3)` LEDs (170 from
channel 1); every next universe holds up to 170 LEDs from slot 1. LEDs beyond universe 63999
are dropped with a log line. This is the usual pixel-controller convention (WLED, xLights,
ESPixelStick: "170 pixels per universe"). OpenRGB's E1.31 controller instead runs the channels
on across the 512-slot boundary (an LED may straddle two universes); that is not used here.

Each universe's packet carries only the slots up to its last LED (slots before `startChannel`
are sent as 0, so other fixtures on the same universe get 0 too: E1.31 has no partial update).

## Packets

One E1.31 data packet per universe per frame, `126 + slots` bytes, all fields big-endian:

| Offset | Field | Value |
|---|---|---|
| 0-1 | preamble size | `00 10` |
| 2-3 | post-amble size | `00 00` |
| 4-15 | ACN packet identifier | `ASC-E1.17` + `00 00 00` |
| 16-17 | root flags + length | `0x7000 \| (length - 16)` |
| 18-21 | root vector | `00 00 00 04` (VECTOR_ROOT_E131_DATA) |
| 22-37 | CID | the controller's CID |
| 38-39 | framing flags + length | `0x7000 \| (length - 38)` |
| 40-43 | framing vector | `00 00 00 02` (VECTOR_E131_DATA_PACKET) |
| 44-107 | source name | `Lightloom`, null-padded to 64 bytes |
| 108 | priority | parameter (default 100 = `0x64`) |
| 109-110 | synchronization address | `00 00` (no sync) |
| 111 | sequence number | per universe, 0..255 then 0 |
| 112 | options | `00`; `40` = Stream_Terminated |
| 113-114 | universe | |
| 115-116 | DMP flags + length | `0x7000 \| (length - 115)` |
| 117 | DMP vector | `02` (SET_PROPERTY) |
| 118 | address type & data type | `A1` |
| 119-120 | first property address | `00 00` |
| 121-122 | address increment | `00 01` |
| 123-124 | property value count | slots + 1 |
| 125 | start code | `00` |
| 126- | DMX slots | colour bytes |

Example (`plugins/e131/fixtures/expected.json`, worked out by hand): two LEDs red, green on
universe 1 is 132 bytes with flags+length `70 74`, `70 5E`, `70 11`, count `00 07` and data
`FF 00 00 00 FF 00`. 172 LEDs from channel 4: universe 1 (169 LEDs, 510 slots, 636 bytes) and
universe 2 (3 LEDs, 9 slots, 135 bytes).

## Rate and shutdown

- The host calls `Render()` at most every 33 ms (under the DMX rate of ~44 Hz). A frame is sent
  when any universe changed, and as a keep-alive after 1 s without a change (receivers treat
  2.5 s of silence as data loss, §6.7.1).
- **Shutdown** (exit or suspend): for each universe that was streamed, three packets with the
  Stream_Terminated option bit (`0x40`) and the last data, as §6.2.6 asks, so the receiver
  releases the universe at once (and falls back to a lower-priority source or its own program).

## On the network (privacy)

Only UDP datagrams with LED colours, by unicast to `<ip>:5568`, while the device runs. The CID
is random and identifies the Lightloom controller entry, nothing else. The service sends nothing.
Nothing leaves the LAN (the host refuses non-local addresses).

## Not implemented

- Multicast (`239.255.<universe hi>.<universe lo>`): unicast to the configured IP is enough for
  one receiver and avoids flooding the LAN.
- Universe discovery packets (E1.31 §8) and synchronization packets (§6.3): optional.
- Preview data option (bit 7) and per-address priority (start code `0xDD`).
- Universe sizes other than 170 LEDs and LEDs split across universes.
